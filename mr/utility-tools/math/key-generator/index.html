सुरक्षित की जनरेटर

ब्राउझरच्या Web Crypto API ने क्रिप्टोग्राफिकदृष्ट्या सुरक्षित API की, एन्क्रिप्शन की आणि ॲक्सेस टोकन तयार करा. HEX, Base64, Base64URL किंवा Base32 निवडा; सर्व काम या उपकरणावर होते.

⚠ हे साधन मशीन-वाचनीय गुपितांसाठी आहे, लक्षात ठेवायच्या लॉगिन पासवर्डसाठी नाही. सुरक्षेच्या गरजेनुसार पुरेसे बाइट निवडा.
⛔ या ब्राउझरमध्ये crypto.getRandomValues समर्थित नाही, त्यामुळे सुरक्षित की तयार होऊ शकत नाही. नवीन Chrome, Firefox, Safari किंवा Edge वापरा.

यादृच्छिक स्रोत: crypto.getRandomValues(), जो क्रिप्टोग्राफिकदृष्ट्या सुरक्षित आहे. रिफ्रेशनंतर की जतन होत नाही; कॉपी किंवा डाउनलोड करून सीक्रेट मॅनेजरमध्ये ठेवा.

एन्कोडिंग स्वरूप

तेच यादृच्छिक बाइट वेगवेगळ्या मजकूर एन्कोडिंगमध्ये दाखवता येतात. URL, JSON, कॉन्फिगरेशन फाइल किंवा प्रोटोकॉलनुसार स्वरूप निवडा.

योग्य: कॉन्फिगरेशन फाइल, कमांड लाइन, लॉग व डीबगिंग.

योग्य: JSON/XML वाहतूक व सामान्य मजकूर साठवण.

योग्य: JWT, OAuth टोकन, कुकी आणि URL पॅरामीटर.

योग्य: TOTP गुपिते, DNS रेकॉर्ड, बारकोड व हाताने नोंद.

वारंवार विचारले जाणारे प्रश्न

हा की जनरेटर सुरक्षित आहे का?

होय. तो Math.random ऐवजी ऑपरेटिंग सिस्टीमच्या सुरक्षित यादृच्छिक स्रोतावर आधारित crypto.getRandomValues वापरतो.

की सर्व्हरवर पाठवल्या किंवा नोंदवल्या जातात का?

नाही. निर्मिती व एन्कोडिंग ब्राउझरमध्ये होते, इतिहास जतन होत नाही आणि रिफ्रेश केल्यावर निकाल नष्ट होतो.

या की लॉगिन पासवर्ड म्हणून वापरू शकतो का?

त्या API की, एन्क्रिप्शन की आणि टोकनसारख्या मशीन-वाचनीय गुपितांसाठी आहेत. मानवी पासवर्डसाठी पासवर्ड मॅनेजर वापरा.

दोन की सारख्या असू शकतात का?

सैद्धांतिकदृष्ट्या शक्य आहे, पण सुचवलेल्या लांबीवर शक्यता नगण्य आहे. 32-बाइट कीचे 2^256 संभाव्य मूल्य असतात.

की कशी साठवावी?

दीर्घकालीन की सीक्रेट मॅनेजर किंवा सुरक्षित पर्यावरण चलात ठेवा; स्रोत कोड, चॅट किंवा लॉगमध्ये टाकू नका आणि नियमितपणे बदला.

की फक्त या ब्राउझरमध्ये तयार होतात आणि सर्व्हरवर कधीही अपलोड होत नाहीत.
